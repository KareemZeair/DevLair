# Conventions for Developer Learning Platform Project

## General Guidelines

1. **Read Documentation**: Before making significant changes, read the following documents:
   - [PROJECT.md](PROJECT.md)
   - [ROADMAP.md](ROADMAP.md)
   - [DECISIONS.md](DECISIONS.md)
   - [AGENTS.md](AGENTS.md)

2. **Preserve Architectural Decisions**: Unless there is a strong reason to change them, preserve existing architectural decisions.

3. **Commit and Push Approval**: Do not commit or push code without my approval.

## Development Philosophy

1. **Act as a Senior Engineer**: Help the developer understand the system by explaining important decisions and avoiding premature complexity.

2. **Simple Solutions**: Prefer simple solutions and avoid unnecessary design patterns or libraries.

3. **Meaningful Tests**: Run tests after meaningful changes and inspect failures rather than blindly modifying code.

## Code Quality

1. **Clear Names**: Use clear and meaningful names for variables, functions, and classes.

2. **Small Cohesive Classes/Functions**: Keep classes and functions small and cohesive.

3. **Explicit Behavior**: Ensure that code has explicit behavior and is easy to understand.

4. **Strong Typing**: Use strong typing where appropriate.

5. **Meaningful Tests**: Write meaningful tests that cover the code's functionality.

6. **Simple Architecture**: Keep the architecture simple and avoid unnecessary complexity.

7. **Consistent Error Handling**: Implement consistent error handling throughout the codebase.

## Workflow

1. **Understand the Requirement**: Clearly understand the requirement before making changes.

2. **Inspect the Relevant Code**: Inspect the relevant code to understand its current state.

3. **Explain the Proposed Approach**: Explain the proposed approach and its benefits.

4. **Implement Incrementally**: Implement changes incrementally to ensure each step is understandable.

5. **Run Tests**: Run tests after each meaningful change to ensure the code works as expected.

6. **Review the Implementation**: Review the implementation to ensure it meets the requirements.

7. **Summarize Changes**: Summarize what changed and any remaining concerns.

## Living Documentation

1. **Update Documentation**: Update the following documents when there are meaningful changes:
   - [PROJECT.md](PROJECT.md)
   - [ROADMAP.md](ROADMAP.md)
   - [DECISIONS.md](DECISIONS.md)
   - [AGENTS.md](AGENTS.md)

2. **Developer Learning Profile**: Record durable new development-process instructions and learning preferences in this section when they are given.

## Important

1. **Uncertainty**: When uncertain about a major product or architecture decision, stop and ask rather than silently choosing a direction that could affect the whole project.

## Development Environment

1. **IntelliJ IDEA**: Use IntelliJ IDEA for development.
2. **Gradle**: Use Gradle for building and managing the project.
